Привязки сессий переживают перезапуск обновлённого ядра.

- Сохраняются явные session ID, aliases и LCP-привязки без текстов диалогов. Снимок зашифрован AES-256-GCM.
- Выбранный аккаунт записывается на диск до запроса к провайдеру. При повреждении хранилища или ошибке записи запрос получает понятную ошибку вместо скрытого переключения.
- Истёкшие привязки не получают новый TTL при восстановлении. Перенос только при подтверждённом исчерпании квоты сохраняется.
- `proxcli hub` и `bun run hub` автоматически включают хранилище. Путь можно задать через `PROXCLI_AFFINITY_FILE`.

Обновление: сохраните приватную копию `.env`, `.data` и OAuth-файлов. Остановите старое ядро, замените пакет и запустите `proxcli hub` и `proxcli serve`. Сохраняйте `affinity.enc` вместе с `affinity.enc.key`; для одного хранилища запускайте одно ядро. Менять режим/TTL affinity рекомендуется при остановленном ядре.

Версия v0.2.0 не записывала привязки. При первом переходе на v0.3.0 восстановить прежнюю RAM-привязку невозможно; последующие привязки будут сохраняться. Кеш находится у провайдера и остаётся доступным только в пределах его собственного TTL. Реальный cache hit на личных аккаунтах не проверялся.

Внутри архивов есть панель, подготовленное ядро и usage-observer. Для запуска Go/Bun не нужны. Пакеты не подписаны сертификатом разработчика. Контрольные суммы опубликованы в `SHA256SUMS`.
